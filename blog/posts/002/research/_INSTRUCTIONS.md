# 002 조사 공통 지시 (모집요강 → research/<id>.md + research/<id>.json)

오늘: 2026-10-02. 목적: 네이버 블로그용 "2027학년도 실용음악과 수시 한눈에 보기" 이미지(학교별 1장)와 본문.
기준 문서: blog/GUIDE.md 7번 (날짜·과제·준비물은 원문 그대로, 추측 금지, 못 찾으면 "요강 확인 필요").

## 해야 할 일
1. 주어진 출처에서 **실용음악 관련 모집단위만** 찾는다 (보컬/악기별/작곡 등 세부 전공 포함). 다른 학과는 무시.
2. `research/<id>.md`를 새로 쓴다(기존 내용 덮어씀): 항목마다 근거 페이지(p.xx) 또는 기사 URL을 단다.
   - 모집단위 정식 명칭·캠퍼스, 전형명, 모집인원(전공별), 전형 요소·반영 비율, 단계별 선발
   - 일정: 원서 접수, 서류/영상 제출, 실기고사(전공별), 합격 발표, (해당 시) 실기 순서 조회·예약
   - 전공별 실기 과제: 곡 수, 지정/자유, 시간, 반주(MR/AR/반주자/무반주), 초견·청음·면접 등
   - 준비물: 수험표·신분증, 악기, 음원 파일(형식·제출 방법), 악보 부수 등
   - 수능최저
3. `research/<id>.json`에 이미지용 요약을 쓴다. 아래 스키마 그대로, **짧게**(한 항목 대략 40자 이내, 원문 뜻 그대로):

```json
{
  "id": "<id>", "name": "대학 정식명", "unit": "모집단위 정식 명칭", "unitShort": "짧은 명칭", "campus": "캠퍼스(요강에 있으면)",
  "summary": { "apply": "9.8(월)–9.12(금)", "exam": "10.1(목)–10.11(일)", "result": "10.30(금)" },
  "tracks": [ { "name": "전형명", "quota": "모집인원 요약", "ratio": [["실기", 80], ["학생부", 20]], "note": "단계별 선발 등 한 줄" } ],
  "csat": "없음 / 있음(내용)",
  "schedule": [["원서 접수", "..."], ["실기 고사", "..."], ["합격 발표", "..."]],
  "exams": [ { "major": "보컬", "items": ["자유곡 1곡 (MR)", "..."] } ],
  "bring": ["수험표", "신분증", "..."],
  "notes": ["꼭 알아야 할 유의사항 1–3개"]
}
```
- 날짜 표기: `10.17(토)` 형식, 범위는 `–`(en dash). 시간이 중요하면 `10.17(토) 10:00`.
- 악기 전공이 많으면 비슷한 것끼리 묶어도 되지만(예: "기타·베이스"), 과제가 다르면 나눈다. exams는 최대 6블록.
- 요강에서 확인 못 한 값은 문자열 "요강 확인 필요". 지어내지 않는다.
- ratio 합은 100. 단계가 있으면 최종 단계 기준으로 쓰고 note에 1단계를 적는다.

4. 끝나면 3–5줄 보고: 확인한 것, 빠진 것, 헷갈린 점(예: 전형이 여러 개).
